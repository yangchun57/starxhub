# Epic 2：商业化基础设施

## 一、Epic 概览

| 属性 | 详情 |
|---|---|
| **Epic 名称** | 商业化基础设施 |
| **业务目标** | 建立付费模式，实现收入 |
| **成功指标** | ① 付费客户数 ≥ 10 家<br>② 月经常性收入（MRR）≥ 5 万/月<br>③ 付费转化率 ≥ 5% |
| **优先级** | 🟠 P1 |
| **预计周期** | 第 2-3 月（8 周） |
| **依赖** | Epic 1（多租户简化）完成 |

---

## 二、用户故事清单

### US-2.1：订阅计划管理

**优先级**：🔴 P0  
**依赖**：US-1.1（租户创建）  
**预计工期**：3 周

**用户故事**：
```
作为租户管理员，
我希望选择不同的订阅计划，
以便根据团队规模和需求付费。
```

**验收标准**：
- 提供 3 种订阅计划（免费版/专业版/企业版）
- 支持月付和年付（年付享 8 折）
- 计划升级/降级实时生效
- 降级时保留数据，超出配额部分只读

**订阅计划设计**：
| 计划 | 价格 | Token 配额 | 用户数 | 功能 |
|---|---|---|---|---|
| **免费版** | 0 元 | 10 万/月 | ≤ 5 人 | 基础代码补全 |
| **专业版** | 299 元/月 | 100 万/月 | ≤ 50 人 | 全功能 + 优先支持 |
| **企业版** | 定制 | 无限 | 不限 | 全功能 + 专属部署 + SLA |

---

### US-2.2：用量计费系统

**优先级**：🔴 P0  
**依赖**：US-1.3（用量统计）  
**预计工期**：4 周

**用户故事**：
```
作为租户管理员，
我希望按实际用量计费，
以便控制成本并避免浪费。
```

**验收标准**：
- 支持 3 种计费模式：按 Token、按用户数、按功能模块
- 超额部分按阶梯价格计费（1.5 倍）
- 账单每月 1 号生成，支持下载 PDF
- 账单数据与用量统计一致（误差 < 0.1%）

**计费规则**：
| 计费项 | 单价 | 阶梯 |
|---|---|---|
| Token（输入） | 0.02 元/千 Token | > 100 万部分 0.03 元 |
| Token（输出） | 0.06 元/千 Token | > 100 万部分 0.09 元 |
| 额外用户 | 20 元/人/月 | - |
| 高级功能（代码审查） | 99 元/月 | - |

---

### US-2.3：支付集成

**优先级**：🔴 P0  
**依赖**：US-2.2（计费系统）  
**预计工期**：3 周

**用户故事**：
```
作为租户管理员，
我希望通过微信/支付宝支付账单，
以便快速完成付款。
```

**验收标准**：
- 支持微信支付、支付宝、Stripe（海外）
- 支付成功后自动续费订阅
- 支付失败时发送提醒邮件/短信
- 支持手动充值（预付费模式）

**支付流程**：
```
账单生成 → 邮件通知 → 用户点击支付链接 → 选择支付方式 → 完成支付 → 自动续费
```

---

### US-2.4：用量告警与限制

**优先级**：🟠 P1  
**依赖**：US-2.2（计费系统）  
**预计工期**：2 周

**用户故事**：
```
作为租户管理员，
我希望设置用量告警阈值，
以便在超额前收到提醒。
```

**验收标准**：
- 支持设置 3 个告警阈值（80%、90%、100%）
- 达到阈值时发送邮件/短信/站内信
- 支持设置硬限制（达到 100% 后暂停服务）
- 告警记录可查询（时间、阈值、实际用量）

---

### US-2.5：发票与财务对账

**优先级**：🟡 P2  
**依赖**：US-2.3（支付集成）  
**预计工期**：2 周

**用户故事**：
```
作为租户管理员，
我希望申请增值税专用发票，
以便进行财务报销。
```

**验收标准**：
- 支持申请增值税普通发票和专用发票
- 发票信息可维护（公司名称、税号、地址）
- 发票状态可查询（申请中/已开具/已邮寄）
- 财务对账报表（收入/退款/坏账）

## 四、交付计划

| 周次 | 里程碑 | 交付内容 | 验收标准 |
|---|---|---|---|
| **第 1-3 周** | M1：订阅计划 | US-2.1 计划管理 + 升级/降级 | 3 种计划可切换 |
| **第 2-5 周** | M2：计费系统 | US-2.2 用量计费 + 账单生成 | 账单误差 < 0.1% |
| **第 4-6 周** | M3：支付集成 | US-2.3 微信/支付宝支付 | 支付成功率 > 99% |
| **第 5-6 周** | M4：用量告警 | US-2.4 告警阈值 + 通知 | 告警延迟 < 1 分钟 |
| **第 7-8 周** | M5：发票系统 | US-2.5 发票申请 + 对账 | 发票状态准确 |
| **第 8 周** | M6：联调上线 | 全流程测试 + 上线 | 首批付费客户上线 |

## 六、风险与缓解

| 风险 | 影响 | 概率 | 缓解措施 |
|---|---|---|---|
| 支付渠道审核延期 | 高 | 中 | 提前申请，预留 2 周缓冲 |
| 计费逻辑复杂导致 Bug | 高 | 中 | 充分测试，上线前双算校验 |
| 定价策略不合理 | 中 | 中 | 上线前调研 5-10 家目标客户 |
| 发票合规问题 | 高 | 低 | 咨询财务顾问，确保合规 |
