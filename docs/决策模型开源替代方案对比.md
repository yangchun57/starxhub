> 调研日期：2026-10-11
> 目标：对比 Microsoft-Decision-1 的开源替代方案，评估本地部署可行性

## 一、核心结论

**✅ 有多个高质量开源替代方案**，且部分方案在延迟、成本、数据合规方面优于微软托管方案。

## 三、重点开源方案详解

### 3.1 AWS Strands Decider 2B ⭐ 推荐入门

**核心优势**：
- ✅ **完全开源**：权重 + 训练代码 + 数据全部公开
- ✅ **极小体积**：2B 参数，LoRA 适配器仅 1M 参数
- ✅ **训练成本低**：8×H100 约 70 分钟，单卡 RTX 3090 约 11 小时
- ✅ **CPU 可跑**：M3 MacBook 中位延迟 150ms

**技术细节**：
```
基座：Qwen3.5-2B-Base
适配器：rank-16 LoRA（约 1M 参数）
架构：替换 next-token head → pointer head（直接评分选项）
输出：概率分布（非文本）
问题类型：noul / choice / score
```

**性能指标**：
- JevBench 准确率：72.3%（167/231）
- Brier Score：0.348（概率校准质量）
- 预期校准误差：0.050
- RTX 3090 延迟：106ms 中位，296ms P95
- M3 MacBook 延迟：~150ms 中位

**适用场景**：
- 资源受限环境（笔记本、边缘设备）
- 需要完全控制训练流程
- 数据合规要求严格（数据不出境）

**获取方式**：
- 权重：Hugging Face（Apache 2.0）
- 代码：GitHub（Strands Labs）

---

### 3.2 Cloudflare Clef-flash ⭐ 推荐生产部署

**核心优势**：
- ✅ **极低延迟**：38.8ms 中位（比 Jev 快 13 倍）
- ✅ **多模态支持**：文本 + JSON + 图像 + 视频
- ✅ **64K 上下文**：是微软的 2 倍
- ✅ **Jev API 兼容**：现有代码无需重写
- ✅ **RL 微调支持**：可用私有数据定制

**技术细节**：
```
基座：Qwen3.5-9B
参数：9B
上下文：64K tokens
输入：文本、JSON、图像、视频
输出：概率分布
训练方法：RLCD（Reinforcement Learning for Calibrated Decisions）
架构：两阶段注意力路由 + 并行选项评分
```

**性能指标**：
- BFCL：98.76%
- BANKING77：94.2 macro-F1（Jev 79.7）
- API-Bank：93.11%
- 延迟：38.8ms 中位（43 基准测试）
- 对比 Jev：524.1ms → 快 13.5 倍

**部署选项**：
1. **Workers AI 托管**：$0.09/M tokens（输入）
2. **本地部署**：Apache 2.0 权重免费下载

**适用场景**：
- 高频决策（Agent 工作流中的热路径）
- 需要多模态输入
- 需要长上下文（64K）
- 需要企业级微调服务

**获取方式**：
- 权重：Hugging Face（Apache 2.0）
- 托管：Cloudflare Workers AI

---

### 3.3 Laya ⭐ 推荐 CPU/边缘部署

**核心优势**：
- ✅ **超小体积**：421M 参数（322M 多语言版）
- ✅ **CPU 可跑**：无需 GPU
- ✅ **超低延迟**：32.8ms（T4 GPU）
- ✅ **100+ 语言支持**：自动检查点路由
- ✅ **完全开源**：权重 + 训练代码 + 数据

**技术细节**：
```
基座：ModernBERT-large（395M）+ 决策头（26M）
参数：421M（英文）/ 322M（多语言）
架构：非自回归 System One 引擎
训练方法：RLCD（严格适当评分规则的强化学习）
检查点：3 个（英文、多语言、类型化决策）
```

**性能指标**：
- 延迟：32.8ms（T4 GPU）
- 准确率：76.6%（2000 决策评估集）
- 零样本基线：36.2%（低于多数类基线 46.1%）
- 微调后：76.6%

**⚠️ 注意事项**：
- 零样本性能较弱，需要微调
- 76.6% 准确率的检查点是在基准训练集上微调的
- 需要自有标注数据才能获得最佳效果

**适用场景**：
- CPU 环境（笔记本、边缘设备）
- 多语言场景（100+ 语言）
- 有标注数据可微调
- 超低延迟要求（60FPS 实时决策）

**获取方式**：
```bash
pip install laya
# 权重自动从 Hugging Face 下载
```

---

### 3.4 Jeff ⭐ 推荐快速原型

**核心优势**：
- ✅ **超快推理**：22-28ms（RTX PRO 6000 / M4 Max）
- ✅ **Jev 兼容**：API 完全兼容
- ✅ **家庭训练**：单卡 RTX PRO 6000 训练 2 小时
- ✅ **多尺寸选择**：0.8B / 2B / 4B / 9B / 27B

**技术细节**：
```
基座：Qwen3.5
参数：0.8B - 27B
训练硬件：1×RTX PRO 6000 + 2×DGX Spark（生成合成数据）
训练时间：0.8B 约 2 小时，2B 约 3.5 小时
API：Jev 兼容（System One）
```

**性能指标**：
- 0.8B 准确率：79.1%（5 基准面板）
- 2B 准确率：83.1%（接近 Jev 的 83.0%）
- Financial PhraseBank：96.4%（0.8B，Jev 77.0%）
- RAGTruth：88.9%（2B）
- 延迟：22ms（RTX PRO 6000）/ 28ms（M4 Max MLX）

**⚠️ 局限性**：
- 推理密集型任务表现较弱（BBH 64.0% vs Jev 94.3%）
- 小型模型不做多步推理，仅做快速校准决策

**适用场景**：
- 快速原型验证
- 分类密集型任务
- 需要本地训练（隐私要求）
- 资源有限但有消费级 GPU

**获取方式**：
- 权重：Hugging Face（Apache 2.0）
- 代码：GitHub

## 四、Cloud Code 插件接入推荐方案

### 4.1 方案 A：Clef-flash 本地部署（推荐）

**理由**：
- 延迟最低（38.8ms），适合实时交互
- 多模态支持（未来扩展性）
- 64K 上下文（长文档处理）
- Jev API 兼容（生态成熟）
- Apache 2.0（无商业限制）

**部署架构**：
```
Cloud Code 插件
    ↓
Decision Gateway（本地服务）
    ↓
Clef-flash（本地 GPU 推理）
    ↓
返回概率分布
```

**硬件需求**：
- GPU：RTX 3060 12GB 或更高（9B 模型需 ~18GB VRAM）
- 或 CPU：M3 MacBook（延迟 ~150ms）

**成本**：
- 一次性硬件投入
- 推理成本：$0（本地）
- 或 Workers AI：$0.09/M tokens

---

### 4.2 方案 B：Laya CPU 部署（资源受限场景）

**理由**：
- 无需 GPU，CPU 即可运行
- 超低延迟（32.8ms）
- 多语言支持
- 完全开源

**部署架构**：
```
Cloud Code 插件
    ↓
Laya 本地服务（CPU）
    ↓
返回概率分布
```

**硬件需求**：
- CPU：任意现代 CPU（4 核+）
- 内存：4GB+
- 无需 GPU

**成本**：
- $0（完全本地）

**⚠️ 注意**：
- 需要微调以获得最佳效果
- 零样本性能较弱

---

### 4.3 方案 C：Strands Decider 2B（入门级）

**理由**：
- 体积最小（2B）
- 训练成本低
- 完全开源（权重+代码+数据）
- 适合学习和实验

**部署架构**：
```
Cloud Code 插件
    ↓
Strands Decider 2B（本地）
    ↓
返回概率分布
```

**硬件需求**：
- GPU：RTX 3090（106ms）或更低
- 或 CPU：M3 MacBook（150ms）

**成本**：
- $0（完全本地）

## 五、开源 vs 微软托管方案对比

| 维度 | 开源方案 | Microsoft-Decision-1 |
|------|----------|----------------------|
| **数据合规** | ✅ 数据不出境 | ❌ 数据发送至微软服务器 |
| **成本** | ✅ $0（本地）或极低 | $0.042/M tokens |
| **延迟** | ✅ 22-150ms（本地） | 85ms P50（托管） |
| **可控性** | ✅ 完全控制（权重+微调） | ❌ 权重不公开，持续更新 |
| **准确率** | ⚠️ 60-83%（视模型） | 83.5%（微软声称） |
| **部署复杂度** | ⚠️ 需要自建推理服务 | ✅ 即开即用 |
| **生态成熟度** | ⚠️ 新兴，文档较少 | ✅ 微软生态支持 |
| **国内可达性** | ✅ 本地部署无网络依赖 | ⚠️ 需访问 OpenRouter/Azure |

## 六、推荐决策树

```
是否需要数据不出境？
├─ 是 → 选择开源方案
│   ├─ 有 GPU（RTX 3060+）？
│   │   ├─ 需要多模态/长上下文？ → Clef-flash
│   │   ├─ 需要超低延迟（<50ms）？ → Jeff 0.8B/2B
│   │   └─ 资源有限（2B 即可）？ → Strands Decider 2B
│   └─ 仅 CPU？
│       ├─ 有标注数据可微调？ → Laya
│       └─ 无标注数据？ → GLiNER2.5-Decide（340M）
└─ 否 → 可选择托管方案
    ├─ 预算敏感？ → OpenRouter (Microsoft-Decision-1)
    └─ 需要企业 SLA？ → Microsoft Foundry
```
