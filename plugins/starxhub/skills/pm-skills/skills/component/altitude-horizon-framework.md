# Altitude-Horizon 框架

## 类型
Component Skill

## 用途
理解 PM→Director 的思维转变：海拔（范围）× 视野（时间）

## 耗时
10-30 分钟

## 框架原理

PM 和 Director 的核心区别：

| 维度 | PM | Director |
|---|---|---|
| **海拔（Altitude）** | 单个产品/功能 | 产品组合/业务线 |
| **视野（Horizon）** | 当前迭代/季度 | 6-18 个月 |
| **关注点** | 怎么做（How） | 做什么（What）和为什么（Why） |
| **决策** | 战术决策 | 战略决策 |
| **影响** | 团队内部 | 跨团队/组织 |

## 四个转型区域

```
高视野（18 月+）
    │
    ├── 战略愿景（高海拔 + 高视野）
    │   Director 的终极目标
    │
    ├── 产品战略（高海拔 + 低视野）
    │   Director 的当前 focus
    │
    ├── 战术执行（低海拔 + 低视野）
    │   PM 的当前 focus
    │
    └── 运营优化（低海拔 + 高视野）
        PM 的长期改进
    │
低视野（当前迭代）
低海拔                              高海拔
```

## 转型检查清单

- [ ] 能从单个产品视角提升到产品组合视角
- [ ] 能从当前迭代视角提升到 6-18 个月视角
- [ ] 能从"怎么做"转向"做什么"和"为什么"
- [ ] 能从团队内部影响扩展到跨团队影响
- [ ] 能从战术决策转向战略决策

## 反模式

- ❌ 只做战术执行：不提升海拔和视野
- ❌ 只做战略愿景：不落地执行
- ❌ 忽视跨团队影响：只关注团队内部
