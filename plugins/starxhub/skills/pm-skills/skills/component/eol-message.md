# 下线通知（EOL Message）

## 类型
Component Skill

## 用途
优雅地沟通产品/功能下线，减少用户流失

## 耗时
10-30 分钟

## 框架原理

下线沟通的关键：
- **提前通知**：给用户足够时间迁移
- **解释原因**：让用户理解为什么
- **提供替代**：帮助用户找到新方案
- **表达感谢**：感谢用户的支持

## 模板

```markdown
## 下线通知

**产品/功能**：{名称}
**下线日期**：{YYYY-MM-DD}
**通知日期**：{YYYY-MM-DD}

---

### 通知标题
{产品/功能名} 将于 {日期} 下线

### 通知正文

亲爱的用户，

感谢您一直以来对 {产品/功能名} 的支持。

**下线原因**：
{解释原因，如技术升级、战略调整、用户量不足等}

**时间线**：
- {日期}：停止新用户注册
- {日期}：停止服务
- {日期}：数据删除

**替代方案**：
我们建议您迁移到 {替代产品/功能}，
它提供了 {优势}。

迁移指南：{链接}

**数据导出**：
您可以在 {日期} 前导出您的数据。
导出方法：{步骤}

**联系我们**：
如有问题，请联系 {联系方式}。

感谢您的理解与支持。

{团队名称}

---

### 多渠道通知计划

| 渠道 | 时间 | 内容 |
|---|---|---|
| 邮件 | 下线前 60 天 | 正式通知 |
| 应用内 | 下线前 30 天 | 横幅提醒 |
| 邮件 | 下线前 7 天 | 最后提醒 |
| 邮件 | 下线当天 | 服务终止 |
```
