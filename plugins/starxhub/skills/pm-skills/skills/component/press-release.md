# 新闻稿（Press Release）

## 类型
Component Skill

## 用途
Amazon Working Backwards 方法：先写新闻稿，再写代码

## 耗时
30-60 分钟

## 框架原理

Working Backwards 的核心：从客户体验倒推产品设计。

先回答：如果产品发布，新闻稿会怎么写？

## 模板

```markdown
# 新闻稿

**产品名称**：{名称}
**发布日期**：{YYYY-MM-DD}
**联系人**：{姓名}

---

## {吸引眼球的标题}

### {副标题：一句话说明核心价值}

**{城市}，{日期}** — {公司名}今天发布了{产品名}，
{一句话描述产品做什么}。

{目标客户}一直面临{问题}。
{产品名}通过{核心功能}，
帮助客户{核心价值}。

"{客户引用}"，{客户姓名}，{客户职位}说。
"{使用产品后的改变}。"

{产品名}包含以下核心功能：
- {功能 1}：{描述}
- {功能 2}：{描述}
- {功能 3}：{描述}

"{团队引用}"，{团队姓名}，{团队职位}说。
"{我们为什么要做这个产品}。"

{产品名}现已{可用/即将上线}。
了解更多信息，请访问{网址}。

---

### 常见问题（FAQ）

**Q：{问题 1}？**
A：{回答}

**Q：{问题 2}？**
A：{回答}

**Q：{问题 3}？**
A：{回答}
```

## 反模式

- ❌ 技术导向：从客户价值出发，不是技术特性
- ❌ 没有客户引用：用客户视角验证价值
- ❌ 忽视 FAQ：FAQ 是产品定义的一部分
