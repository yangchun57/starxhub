# 用户故事（User Story）

## 类型
Component Skill

## 用途
编写符合 Mike Cohn 格式的用户故事，包含 Gherkin 验收标准

## 耗时
10-30 分钟

## 框架原理

用户故事是敏捷开发中捕获需求的最小单元，遵循 INVEST 原则：
- **I**ndependent（独立）：故事之间尽量独立
- **N**egotiable（可协商）：不是合同，是对话的起点
- **V**aluable（有价值）：对用户或业务有价值
- **E**stimable（可估算）：团队能估算工作量
- **S**mall（小的）：足够小，能在一个迭代内完成
- **T**estable（可测试）：有明确的验收标准

## 标准格式

```
作为 [用户角色]，
我希望 [功能/行为]，
以便 [业务价值/目标]。
```

## 验收标准（Gherkin 格式）

```gherkin
Given [前置条件]
When [用户操作]
Then [预期结果]
And [附加条件]
```

## 执行步骤

1. **明确用户角色**
   - 谁在使用这个功能？
   - 他们的目标是什么？

2. **定义功能/行为**
   - 用户想要做什么？
   - 系统应该如何响应？

3. **阐述业务价值**
   - 为什么需要这个功能？
   - 它解决了什么问题？

4. **编写验收标准**
   - 什么情况下算完成？
   - 边界条件是什么？

## 示例

### 示例 1：多租户创建

```
作为 租户管理员，
我希望 通过预设模板快速创建租户，
以便 在 10 分钟内完成上线。

验收标准：
Given 租户管理员进入创建页面
When 选择"标准版"模板并填写租户名称
Then 系统在 10 分钟内完成租户创建
And 自动初始化数据库 Schema 和默认权限
And 发送创建完成通知到管理员邮箱
```

### 示例 2：代码补全

```
作为 开发者，
我希望 在输入代码时获得智能补全建议，
以便 提高编码效率。

验收标准：
Given 开发者在编辑器中输入代码
When 暂停输入 200ms
Then 显示最多 5 个补全建议
And 按相关性排序
And 支持键盘上下键选择
```

## 反模式警示

### ❌ 反模式 1：技术实现导向
```
错误：作为系统，我需要创建数据库表...
正确：作为租户管理员，我希望快速创建租户...
```

### ❌ 反模式 2：验收标准模糊
```
错误：Then 系统应该正常工作
正确：Then 系统在 10 分钟内完成创建，成功率 > 99%
```

### ❌ 反模式 3：故事过大
```
错误：作为用户，我希望管理整个系统...
正确：拆分为多个小故事（创建/编辑/删除/权限）
```

## 质量检查清单

- [ ] 遵循 "作为...我希望...以便..." 格式
- [ ] 用户角色明确（不是"系统"或"用户"）
- [ ] 业务价值清晰
- [ ] 验收标准可测试（Given/When/Then）
- [ ] 故事足够小（能在一个迭代内完成）
- [ ] 无技术实现细节
