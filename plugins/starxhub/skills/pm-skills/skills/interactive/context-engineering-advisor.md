# 上下文工程顾问（Context Engineering Advisor）

## 类型
Interactive Skill

## 用途
诊断上下文堆砌 vs 上下文工程，指导记忆架构设计

## 耗时
30-60 分钟

## 框架原理

两种上下文管理方式：

| 方式 | 定义 | 问题 |
|---|---|---|
| **上下文堆砌** | 把所有信息塞进提示词 | 信息过载，效果下降 |
| **上下文工程** | 结构化设计上下文 | 精准投放，效果提升 |

## 交互流程

### 第一步：诊断当前状态（20 分钟）

**核心问题**：
1. 你如何管理上下文？
2. 提示词有多长？
3. 效果如何？

**输出**：
```markdown
## 上下文工程诊断

### 当前状态
- **提示词长度**：{字数}
- **上下文来源**：{来源}
- **效果评分**：{分}/10

### 问题识别
- [ ] 上下文堆砌（信息过载）
- [ ] 缺乏结构化（信息混乱）
- [ ] 缺乏记忆（重复输入）
- [ ] 缺乏检索（找不到信息）

### 诊断结果
**当前方式**：{上下文堆砌/上下文工程}
**主要问题**：{问题}
```

### 第二步：设计记忆架构（20 分钟）

**输出**：
```markdown
## 记忆架构设计

### 记忆层级
| 层级 | 内容 | 存储 | 检索 |
|---|---|---|---|
| 短期记忆 | 当前对话 | 内存 | 直接访问 |
| 工作记忆 | 当前任务 | 文件 | 按需加载 |
| 长期记忆 | 知识库 | 数据库 | 语义检索 |

### 检索策略
- **触发条件**：{条件}
- **检索方式**：{方式}
- **注入方式**：{方式}

### 研究→计划→重置→实现循环
1. **研究**：理解上下文
2. **计划**：设计架构
3. **重置**：清理无关信息
4. **实现**：落地执行
```

### 第三步：制定改进计划（20 分钟）

**输出**：
```markdown
## 改进计划

### 短期（1 个月）
- [ ] {行动 1}
- [ ] {行动 2}

### 中期（3 个月）
- [ ] {行动 1}
- [ ] {行动 2}

### 成功指标
- {指标 1}
- {指标 2}
```

## 反模式

- ❌ 上下文堆砌：塞入所有信息
- ❌ 忽视检索：只存储不检索
- ❌ 缺乏重置：不清理无关信息
