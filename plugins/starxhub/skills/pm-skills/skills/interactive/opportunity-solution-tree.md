# 机会方案树（Opportunity Solution Tree）

## 类型
Interactive Skill

## 用途
基于 Teresa Torres 框架，生成机会→方案→实验的决策树，推荐最值得测试的 POC

## 耗时
30-90 分钟

## 框架原理

机会方案树（OST）是持续发现框架的核心工具，帮助团队：
- **聚焦机会**：不是先想方案，而是先找机会
- **多方案探索**：每个机会探索多个方案
- **快速验证**：选择最小实验验证假设

## 执行流程

### 第一步：定义期望成果（10 分钟）

**核心问题**：
1. 业务目标是什么？
2. 成功指标是什么？
3. 时间范围？

**输出**：
```markdown
## 期望成果

**业务目标**：{目标}
**成功指标**：{指标}
**时间范围**：{时间}
```

### 第二步：识别机会（20 分钟）

**机会来源**：
- 用户访谈（痛点、需求）
- 数据分析（行为、反馈）
- 竞品分析（差距、趋势）
- 团队洞察（经验、直觉）

**机会描述格式**：
```
用户需要 [做什么]，但 [遇到什么障碍]
```

**输出**：
```markdown
## 机会清单

| 机会 | 来源 | 影响用户 | 严重性 |
|---|---|---|---|
| {机会 1} | {来源} | {用户群} | {高/中/低} |
```

### 第三步：生成方案（20 分钟）

**方案生成原则**：
- 每个机会至少 3 个方案
- 方案要多样化（功能/流程/商业模式）
- 不急于评判，先发散

**输出**：
```markdown
## 方案清单

### 机会 1：{机会描述}
- 方案 1A：{方案}
- 方案 1B：{方案}
- 方案 1C：{方案}

### 机会 2：{机会描述}
- 方案 2A：{方案}
- 方案 2B：{方案}
- 方案 2C：{方案}
```

### 第四步：评估方案（20 分钟）

**评估维度**：
- **价值**：对用户的价值有多大？
- **可行性**：技术上能实现吗？
- **风险**：最大的不确定性是什么？

**评估方法**：
```
价值：高/中/低
可行性：高/中/低
风险：高/中/低

优先级 = 价值高 + 可行性高 + 风险低
```

**输出**：
```markdown
## 方案评估

| 机会 | 方案 | 价值 | 可行性 | 风险 | 优先级 |
|---|---|---|---|---|---|
| 机会 1 | 方案 1A | 高 | 高 | 低 | 🔴 P0 |
| 机会 1 | 方案 1B | 高 | 中 | 中 | 🟠 P1 |
| 机会 1 | 方案 1C | 中 | 高 | 低 | 🟡 P2 |
```

### 第五步：设计实验（20 分钟）

**实验类型**：
- **访谈实验**：验证问题和方案吸引力
- **原型实验**：验证交互和流程
- **A/B 测试**：验证方案效果
- **Wizard of Oz**：验证需求真实性

**实验设计**：
```markdown
## 实验设计

**实验名称**：{名称}
**假设**：如果我们 [做什么]，那么 [预期结果]
**验证指标**：{指标}
**成功标准**：{标准}
**最小实验**：{最小可执行版本}
**预计时间**：{时间}
```

### 第六步：推荐 POC（10 分钟）

**推荐逻辑**：
```
IF 风险高 AND 价值高:
    推荐：访谈实验（先验证问题）
    
IF 风险中 AND 可行性高:
    推荐：原型实验（快速验证方案）
    
IF 风险低 AND 价值明确:
    推荐：A/B 测试（验证效果）
```

## 反模式警示

### ❌ 反模式 1：方案先行
**问题**：先想方案，再找机会
**解决**：先识别机会，再生成方案

### ❌ 反模式 2：单一方案
**问题**：每个机会只有一个方案
**解决**：每个机会至少 3 个方案

### ❌ 反模式 3：直接开发
**问题**：不做实验，直接开发
**解决**：先做最小实验验证假设
