# Epic 拆分顾问（Epic Breakdown Advisor）

## 类型
Interactive Skill

## 用途
使用 Richard Lawrence 的 9 种模式将大 Epic 拆分为可执行的用户故事

## 耗时
30-90 分钟

## 框架原理

Richard Lawrence 的 9 种拆分模式：
1. **按工作流步骤**：沿用户旅程拆分
2. **按业务规则**：按不同规则路径拆分
3. **按用户角色**：按不同用户类型拆分
4. **按数据类型**：按不同数据类别拆分
5. **按 CRUD 操作**：按创建/读取/更新/删除拆分
6. **按快乐路径/异常路径**：按正常/异常流程拆分
7. **按质量等级**：按性能/可用性等级拆分
8. **按 MVP 范围**：按必需/可选拆分
9. **按技术层**：按 UI/业务逻辑/数据层拆分

## 交互流程

### 第一步：理解 Epic（10 分钟）

**核心问题**：
1. Epic 的目标是什么？
2. 涉及哪些用户角色？
3. 包含哪些核心功能？

### 第二步：选择拆分模式（10 分钟）

**推荐逻辑**：
```
IF Epic 涉及多个用户角色:
    推荐：按用户角色拆分
    
IF Epic 包含多种数据类型:
    推荐：按数据类型拆分
    
IF Epic 有明显的工作流:
    推荐：按工作流步骤拆分
    
IF Epic 包含多种业务规则:
    推荐：按业务规则拆分
    
IF Epic 需要快速交付 MVP:
    推荐：按 MVP 范围拆分
```

### 第三步：执行拆分（20 分钟）

**输出**：
```markdown
## Epic 拆分结果

**Epic 名称**：{名称}
**拆分模式**：{模式}

### 拆分后的用户故事

| # | 用户故事 | 估算 | 优先级 | 依赖 |
|---|---|---|---|---|
| 1 | {故事} | {点} | {P0/P1/P2} | {依赖} |
| 2 | {故事} | {点} | {P0/P1/P2} | {依赖} |

### 拆分理由
{解释为什么选择这种拆分方式}

### 依赖关系
{故事之间的依赖关系图}
```

## 反模式

- ❌ 拆分过细：故事太小，失去上下文
- ❌ 忽视依赖：拆分后故事之间有隐含依赖
- ❌ 强制均匀拆分：不是所有故事都一样大
