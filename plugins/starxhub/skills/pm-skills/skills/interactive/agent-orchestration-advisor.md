# Agent 编排顾问（Agent Orchestration Advisor）

## 类型
Interactive Skill

## 用途
指导多 Agent 工作流设计，覆盖 4 个维度

## 耗时
30-60 分钟

## 框架原理

多 Agent 编排的 4 个维度：

| 维度 | 问题 |
|---|---|
| **任务分解** | 如何拆分任务给不同 Agent？ |
| **协调机制** | Agent 之间如何协调？ |
| **状态管理** | 如何管理共享状态？ |
| **错误处理** | 如何处理 Agent 失败？ |

## 交互流程

### 第一步：理解需求（15 分钟）

**核心问题**：
1. 需要哪些 Agent？
2. 任务如何分解？
3. Agent 之间如何协调？

### 第二步：设计编排（25 分钟）

**输出**：
```markdown
## Agent 编排设计

### Agent 清单
| Agent | 职责 | 输入 | 输出 |
|---|---|---|---|
| {Agent 1} | {职责} | {输入} | {输出} |

### 工作流
```
{Agent 1} → {Agent 2} → {Agent 3}
   ↓           ↓           ↓
{Agent 4} → {Agent 5} → {Agent 6}
```

### 协调机制
- **同步点**：{描述}
- **消息传递**：{方式}
- **状态共享**：{方式}

### 错误处理
- **失败策略**：{策略}
- **重试机制**：{机制}
- **降级方案**：{方案}
```

### 第三步：制定实施计划（20 分钟）

**输出**：
```markdown
## 实施计划

### 阶段 1：基础框架
- [ ] {任务 1}
- [ ] {任务 2}

### 阶段 2：Agent 实现
- [ ] {任务 1}
- [ ] {任务 2}

### 阶段 3：集成测试
- [ ] {任务 1}
- [ ] {任务 2}

### 风险与缓解
- **风险**：{风险}
- **缓解**：{缓解措施}
```

## 反模式

- ❌ 过度复杂：不是所有任务都需要多 Agent
- ❌ 忽视协调：Agent 之间需要明确协调
- ❌ 缺乏错误处理：必须考虑失败场景
