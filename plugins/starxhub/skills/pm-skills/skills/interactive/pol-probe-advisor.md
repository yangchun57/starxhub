# 验证实验顾问（PoL Probe Advisor）

## 类型
Interactive Skill

## 用途
根据假设和风险推荐最适合的原型类型

## 耗时
30-60 分钟

## 框架原理

5 种原型类型：

| 类型 | 用途 | 成本 | 速度 |
|---|---|---|---|
| **可行性原型** | 验证技术可行性 | 中 | 中 |
| **任务聚焦原型** | 验证核心任务流程 | 低 | 快 |
| **叙事原型** | 验证用户体验和故事 | 低 | 快 |
| **合成原型** | 模拟真实系统行为 | 高 | 慢 |
| **氛围原型** | 验证视觉和感觉 | 低 | 快 |

## 交互流程

### 第一步：理解假设（15 分钟）

**核心问题**：
1. 要验证什么假设？
2. 最大的风险是什么？
3. 需要多快得到答案？

### 第二步：推荐原型类型（15 分钟）

**推荐逻辑**：
```
IF 风险是技术可行性:
    推荐：可行性原型
    
IF 风险是用户流程:
    推荐：任务聚焦原型
    
IF 风险是用户理解:
    推荐：叙事原型
    
IF 需要模拟真实行为:
    推荐：合成原型
    
IF 风险是视觉/感觉:
    推荐：氛围原型
```

### 第三步：设计实验（20 分钟）

**输出**：
```markdown
## 验证实验设计

**假设**：{假设}
**风险**：{风险}
**推荐原型**：{类型}

### 实验设计
**做什么**：{描述}
**需要多少**：{资源}
**需要多久**：{时间}

### 成功标准
- 主要标准：{标准}
- 次要标准：{标准}

### 下一步
- [ ] {行动 1}
- [ ] {行动 2}
```

## 反模式

- ❌ 过度构建：原型应该最小化
- ❌ 忽视学习：原型的目的是学习，不是交付
- ❌ 不迭代：根据学习结果迭代原型
