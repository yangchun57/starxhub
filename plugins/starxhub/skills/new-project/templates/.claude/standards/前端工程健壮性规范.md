# 前端工程健壮性规范

> 单一事实来源：本文件由历史 topics 手工分片回并生成，章节标题与分片文件名一一对应。
> `topics/` 由 `split-standards.py` 按 `## ` 重建，禁止手改分片；分片正文标题已整体降两级，避免被误切。

## 概述

#### 适用范围

本规范适用于所有 Vue 3 + TypeScript 前端代码，特别是类型定义、错误处理、API 调用。

#### 核心原则

1. **类型安全原则**：禁止运行时代码出现在 `.d.ts` 文件中
2. **错误分类原则**：区分用户取消、业务错误、系统错误，分别处理
3. **空值防护原则**：所有 API 响应必须做空值检查
4. **用户反馈原则**：错误必须给用户明确的反馈，不能只 console.log

#### 问题分类

| 级别 | 说明 | 示例 |
|------|------|------|
| Critical | 导致功能完全失效 | .d.ts 包含运行时代码 |
| High | 导致用户体验差或调试困难 | 错误无反馈、空值未检查 |
| Medium | 代码质量问题 | 类型定义不规范 |

#### 强制检查清单

- [ ] `.d.ts` 文件是否只包含类型声明，无运行时代码
- [ ] 文件上传是否删除手动 `Content-Type` 设置
- [ ] API 响应是否做空值防护
- [ ] 错误处理是否区分用户取消和真实错误
- [ ] 错误是否给用户明确的反馈

## TypeScript类型文件规范

#### 强制规则

##### 1. `.d.ts` 文件只能包含类型声明

```typescript
// ✅ 正确：vite-env.d.ts 只声明类型
/// <reference types="vite/client" />

declare module '*.vue' {
  import type { DefineComponent } from 'vue'
  const component: DefineComponent<{}, {}, any>
  export default component
}

// 环境变量类型
interface ImportMetaEnv {
  readonly VITE_API_BASE_URL: string
  readonly VITE_APP_TITLE: string
}

interface ImportMeta {
  readonly env: ImportMetaEnv
}
```

```typescript
// ❌ 错误：.d.ts 包含运行时代码
// vite-env.d.ts
export const API_BASE_URL = import.meta.env.VITE_API_BASE_URL  // 错误！

export function formatDate(date: Date): string {
  return date.toLocaleDateString()  // 错误！
}

export enum Status {  // 错误！enum 是运行时代码
  Active = 1,
  Inactive = 0
}
```

##### 2. 运行时代码必须放在 `.ts` 文件

```typescript
// ✅ 正确：constants.ts（运行时代码）
export const API_BASE_URL = import.meta.env.VITE_API_BASE_URL

export function formatDate(date: Date): string {
  return date.toLocaleDateString()
}

// ✅ 正确：enums.ts（运行时代码）
export enum Status {
  Active = 1,
  Inactive = 0
}

// ✅ 正确：types.ts（类型定义）
export interface User {
  id: string
  name: string
  status: Status  // 引用 enum
}
```

##### 3. 文件命名规范

```
types/
├── api.d.ts          # 只包含类型声明
├── user.d.ts         # 只包含类型声明
├── constants.ts      # 运行时常量
├── enums.ts          # 运行时代码（enum）
└── utils.ts          # 运行时工具函数
```

##### 4. 使用 `const` 枚举替代 `enum`（可选）

如果确实需要在 `.d.ts` 中定义枚举-like 的值，使用 `const` 对象：

```typescript
// ✅ 正确：使用 const 对象（可以放在 .d.ts）
export const Status = {
  Active: 1,
  Inactive: 0
} as const

export type Status = typeof Status[keyof typeof Status]

// 使用
const status: Status = Status.Active
```

#### 检查方法

```bash
### 查找 .d.ts 中的运行时代码
grep -r "export const\|export function\|export enum" --include="*.d.ts" .

### 应该只看到类型声明
### 如果看到运行时代码，需要重命名为 .ts
```

#### 检查清单

- [ ] `.d.ts` 文件只包含 `interface`、`type`、`declare`
- [ ] 运行时常量放在 `.ts` 文件
- [ ] 运行时函数放在 `.ts` 文件
- [ ] `enum` 放在 `.ts` 文件（或使用 `const` 对象替代）

## 错误处理规范

#### 强制规则

##### 1. 删除操作必须区分用户取消和真实错误

```typescript
// ❌ 错误：catch 块吞掉所有错误
async function handleDelete(id: string) {
  try {
    await ElMessageBox.confirm('确定删除？', '提示', { type: 'warning' })
    await deleteItem(id)
    ElMessage.success('删除成功')
  } catch {
    // 错误！用户取消和真实错误都被吞掉
    console.log('删除取消')
  }
}

// ✅ 正确：区分用户取消和真实错误
async function handleDelete(id: string) {
  try {
    await ElMessageBox.confirm('确定删除？', '提示', { type: 'warning' })
    await deleteItem(id)
    ElMessage.success('删除成功')
    await loadData()
  } catch (error) {
    // 判断是否为用户取消
    if (error === 'cancel' || error?.toString().includes('cancel')) {
      return  // 用户取消，不处理
    }
    
    // 真实错误，给用户反馈
    console.error('删除失败:', error)
    ElMessage.error('删除失败，请重试')
  }
}
```

##### 2. API 调用错误必须给用户反馈

```typescript
// ❌ 错误：只 console.log，用户不知道发生了什么
async function loadData() {
  try {
    const res = await getItems()
    tableData.value = res.data
  } catch (error) {
    console.log('loadData error:', error)  // 错误！用户无感知
  }
}

// ✅ 正确：给用户明确的错误提示
async function loadData() {
  loading.value = true
  try {
    const res = await getItems()
    if (res.code === 200) {
      tableData.value = res.data.items
      total.value = res.data.total
    } else {
      ElMessage.error(res.message || '加载失败')
    }
  } catch (error) {
    console.error('loadData error:', error)
    ElMessage.error('网络错误，请稍后重试')
  } finally {
    loading.value = false
  }
}
```

##### 3. 表单提交错误处理

```typescript
// ✅ 完整示例：表单提交错误处理
async function handleSubmit() {
  // 1. 表单验证
  const valid = await formRef.value?.validate().catch(() => false)
  if (!valid) {
    ElMessage.warning('请检查表单填写')
    return
  }
  
  // 2. 提交数据
  submitting.value = true
  try {
    const res = formData.value.id 
      ? await updateItem(formData.value.id, formData.value)
      : await createItem(formData.value)
    
    if (res.code === 200) {
      ElMessage.success(formData.value.id ? '更新成功' : '创建成功')
      dialogVisible.value = false
      await loadData()
    } else {
      ElMessage.error(res.message || '操作失败')
    }
  } catch (error) {
    // 3. 网络错误或服务器错误
    console.error('提交失败:', error)
    
    if (axios.isAxiosError(error)) {
      if (error.response?.status === 409) {
        ElMessage.error('数据已被修改，请刷新后重试')
      } else if (error.response?.status === 400) {
        ElMessage.error(error.response.data?.message || '请求参数错误')
      } else {
        ElMessage.error('网络错误，请稍后重试')
      }
    } else {
      ElMessage.error('未知错误，请重试')
    }
  } finally {
    submitting.value = false
  }
}
```

##### 4. 封装统一的错误处理工具

```typescript
// utils/error-handler.ts
import { ElMessage } from 'element-plus'
import axios from 'axios'

export function handleError(error: unknown, context?: string) {
  console.error(context ? `${context} error:` : 'Error:', error)
  
  // 用户取消操作
  if (error === 'cancel' || error?.toString().includes('cancel')) {
    return
  }
  
  // Axios 错误
  if (axios.isAxiosError(error)) {
    if (!error.response) {
      ElMessage.error('网络连接失败，请检查网络')
      return
    }
    
    const status = error.response.status
    const message = error.response.data?.message
    
    switch (status) {
      case 400:
        ElMessage.error(message || '请求参数错误')
        break
      case 401:
        ElMessage.error('登录已过期，请重新登录')
        // 跳转到登录页
        break
      case 403:
        ElMessage.error('没有权限执行此操作')
        break
      case 404:
        ElMessage.error('请求的资源不存在')
        break
      case 409:
        ElMessage.error('数据冲突，请刷新后重试')
        break
      case 500:
        ElMessage.error('服务器内部错误')
        break
      default:
        ElMessage.error(message || `请求失败 (${status})`)
    }
    return
  }
  
  // 其他错误
  ElMessage.error('操作失败，请稍后重试')
}

// 使用
async function loadData() {
  try {
    const res = await getItems()
    tableData.value = res.data
  } catch (error) {
    handleError(error, 'loadData')
  }
}
```

#### 检查清单

- [ ] 删除操作的 catch 块区分用户取消和真实错误
- [ ] 所有 API 调用错误给用户明确的反馈
- [ ] 使用 `ElMessage.error()` 而非只 `console.log()`
- [ ] 表单提交处理各种 HTTP 状态码（400/401/403/409/500）
- [ ] 考虑封装统一的错误处理工具函数

## 空值防护规范

#### 强制规则

##### 1. API 响应必须做空值检查

```typescript
// ❌ 错误：直接访问嵌套属性
async function loadData() {
  const res = await getItem(id)
  detail.value = res.data  // 如果 res.data 为 null，后续访问会报错
}

// 模板中使用
// <div>{{ detail.name }}</div>  // 如果 detail 为 null，报错！

// ✅ 正确：做空值检查
async function loadData() {
  const res = await getItem(id)
  if (res.code === 200 && res.data) {
    detail.value = res.data
  } else {
    ElMessage.error(res.message || '加载失败')
    detail.value = null
  }
}

// 模板中使用可选链
// <div>{{ detail?.name || '未设置' }}</div>
```

##### 2. 数组响应必须初始化为空数组

```typescript
// ❌ 错误：未初始化或初始化为 null
const tableData = ref(null)  // 或 let tableData = ref()

async function loadData() {
  const res = await getItems()
  tableData.value = res.data.items  // 如果 items 为 undefined，报错
}

// ✅ 正确：初始化为空数组
const tableData = ref<Item[]>([])

async function loadData() {
  const res = await getItems()
  if (res.code === 200) {
    tableData.value = res.data.items || []  // 兜底空数组
    total.value = res.data.total || 0
  }
}
```

##### 3. 对象响应必须提供默认值

```typescript
// ❌ 错误：直接赋值，可能为 null
const userInfo = ref<UserInfo>()

async function loadUserInfo() {
  const res = await getUserInfo()
  userInfo.value = res.data  // 可能为 null
}

// ✅ 正确：提供默认值
const userInfo = ref<UserInfo>({
  id: '',
  name: '',
  phone: '',
  email: ''
})

async function loadUserInfo() {
  const res = await getUserInfo()
  if (res.code === 200 && res.data) {
    userInfo.value = {
      id: res.data.id || '',
      name: res.data.name || '',
      phone: res.data.phone || '',
      email: res.data.email || ''
    }
  }
}
```

##### 4. 模板中使用可选链和空值合并

```vue
<template>
  <!-- ❌ 错误：直接访问可能为 null 的属性 -->
  <div>{{ user.name }}</div>
  <div>{{ user.address.city }}</div>
  
  <!-- ✅ 正确：使用可选链 -->
  <div>{{ user?.name || '未设置' }}</div>
  <div>{{ user?.address?.city || '未设置' }}</div>
  
  <!-- ✅ 正确：使用 v-if 判断 -->
  <div v-if="user">{{ user.name }}</div>
  
  <!-- ✅ 正确：使用空值合并 -->
  <div>{{ user?.name ?? '未设置' }}</div>
</template>
```

##### 5. 日期格式化必须校验有效性

```typescript
// ❌ 错误：未校验日期有效性
function formatDateTime(dateStr: string) {
  if (!dateStr) return '-'
  return new Date(dateStr).toLocaleString('zh-CN')
  // 如果 dateStr 为 "abc"，返回 "Invalid Date"
}

// ✅ 正确：校验日期有效性
function formatDateTime(dateStr: string) {
  if (!dateStr) return '-'
  
  const date = new Date(dateStr)
  if (isNaN(date.getTime())) {
    console.warn('Invalid date:', dateStr)
    return '-'
  }
  
  return date.toLocaleString('zh-CN')
}
```

#### 检查清单

- [ ] API 响应做空值检查（`res.data` 可能为 null）
- [ ] 数组响应初始化为空数组（`ref([])`）
- [ ] 对象响应提供默认值
- [ ] 模板中使用可选链（`?.`）访问可能为 null 的属性
- [ ] 日期格式化校验有效性
- [ ] 使用 `||` 或 `??` 提供兜底值

## 文件上传与移动端规范

#### 文件上传规范

##### 1. 禁止手动设置 Content-Type

```typescript
// ❌ 错误：手动设置 multipart/form-data
async function uploadFile(file: File) {
  const formData = new FormData()
  formData.append('file', file)
  
  const res = await axios.post('/api/upload', formData, {
    headers: {
      'Content-Type': 'multipart/form-data'  // 错误！
    }
  })
  return res.data
}

// ✅ 正确：让浏览器自动设置（包含 boundary）
async function uploadFile(file: File) {
  const formData = new FormData()
  formData.append('file', file)
  
  // 不设置 Content-Type，浏览器会自动添加正确的 boundary
  const res = await axios.post('/api/upload', formData)
  return res.data
}
```

##### 2. 前端文件校验

```typescript
// ✅ 完整示例：文件上传前校验
const MAX_FILE_SIZE = 5 * 1024 * 1024  // 5 MB
const ALLOWED_TYPES = ['image/jpeg', 'image/png', 'application/pdf']

function validateFile(file: File): string | null {
  // 1. 校验大小
  if (file.size > MAX_FILE_SIZE) {
    return `文件大小不能超过 5MB`
  }
  
  // 2. 校验类型
  if (!ALLOWED_TYPES.includes(file.type)) {
    return `不支持的文件类型: ${file.type}`
  }
  
  return null
}

// 使用
async function handleFileChange(file: File) {
  const error = validateFile(file)
  if (error) {
    ElMessage.error(error)
    return
  }
  
  uploading.value = true
  try {
    const res = await uploadFile(file)
    if (res.code === 200) {
      ElMessage.success('上传成功')
      fileUrl.value = res.data.url
    } else {
      ElMessage.error(res.message || '上传失败')
    }
  } catch (error) {
    handleError(error, 'uploadFile')
  } finally {
    uploading.value = false
  }
}
```

##### 3. 防止重复上传

```typescript

async function handleUpload(file: File) {
  if (uploading.value) {
    ElMessage.warning('正在上传中，请稍候')
    return
  }
  
  uploading.value = true
  try {
    const res = await uploadFile(file)
    // 处理结果...
  } finally {
    uploading.value = false
  }
}
```

#### 移动端规范

##### 1. 手机号输入框使用数字键盘

```vue
<!-- ❌ 错误：使用默认文本键盘 -->
<input type="text" v-model="phone" placeholder="请输入手机号" />

<!-- ✅ 正确：H5 页面使用 inputmode="numeric" -->
<input 
  type="text" 
  inputmode="numeric" 
  pattern="[0-9]*"
  v-model="phone" 
  placeholder="请输入手机号" 
/>

<!-- ✅ 正确：小程序使用 type="number" -->
<input type="number" v-model="phone" placeholder="请输入手机号" />
```

##### 2. 表单验证规则

```typescript
// ✅ 手机号验证（支持带空格/横杠的输入）
const phoneRules = [
  { required: true, message: '请输入手机号', trigger: 'blur' },
  {
    validator: (rule: any, value: string, callback: any) => {
      if (!value) {
        callback(new Error('请输入手机号'))
        return
      }
      
      // 移除空格和横杠
      const cleanPhone = value.replace(/[\s-]/g, '')
      
      // 验证格式
      if (!/^1[3-9]\d{9}$/.test(cleanPhone)) {
        callback(new Error('手机号格式不正确'))
        return
      }
      
      callback()
    },
    trigger: 'blur'
  }
]
```

##### 3. 性别字段使用枚举

```typescript

export const GenderLabel: Record<number, string> = {
```
