# 0. 一句话方法论

> **先理解任务，再设计流程；先确定结构，再设计页面；先保证业务闭环，再追求视觉效果；页面既要好看，也必须好用、能演示、能开发。**

> **需求决定页面，任务决定结构，体验决定交互，视觉服务业务；原型范围与实现深度由产品经理结合项目目标、资源和阶段自主决定。**


# 1.本技能能解决什么问题

本技能用于解决以下问题：

1. 领导或客户只给一句模糊需求，如何快速转成 Web 产品；
2. 如何识别真正的用户、使用场景和核心任务；
3. 如何把业务流程转成页面流和交互流；
4. 如何避免“先画菜单、后补业务逻辑”；
5. 如何快速确定首页、列表页、详情页、工作台、对照审核页、AI工作台等页面模式；
6. 如何控制页面数量和一期范围；
7. 如何生成视觉统一、专业、现代、企业级的高保真原型；
8. 如何设计 Loading、Empty、Error、部分成功、待人工确认、无权限等真实状态；
9. 如何设计 AI 执行过程、AI 结果、依据、人工确认和异常降级；
10. 如何把原型直接转换成研发能够理解的页面、字段、交互、状态和接口需求；
11. 如何在不同项目目标、工期和资源条件下保持产品设计质量，并由产品经理自主决定原型范围、优先级和实现深度。


# 2.本技能的设计角色

调用后，本技能 默认同时承担五种角色：

## 2.1 产品需求拆解者
从题目、方案或业务资料中识别：
- 用户；
- 场景；
- 核心痛点；
- 核心任务；
- 核心业务成果；
- 一期范围。

## 2.2 信息架构师
设计：
- 一级导航；
- 二级菜单；
- 页面层级；
- 工作台；
- 详情关系；
- 页面之间的任务路径。

## 2.3 交互设计师
设计：
- 页面跳转；
- 按钮动作；
- 抽屉；
- 弹窗；
- Tab；
- 筛选；
- 状态转换；
- 异常处理；
- 人工确认；
- AI 过程反馈。

## 2.4 UI 设计导演
统一：
- 色彩；
- 字体；
- 间距；
- 圆角；
- 阴影；
- 图标；
- 表格；
- 表单；
- 状态标签；
- 图表；
- 页面密度。

## 2.5 研发交接助手
把原型转换成：
- 页面清单；
- 页面结构；
- 示例数据；
- 字段；
- 组件；
- 点击行为；
- AI 调用点；
- API 需求；
- 待研发确认项。


# 3. 第一原则：Web 原型不是页面集合，而是任务系统

任何 Web 原型设计必须先回答：

> **用户为什么进入系统？**
>
> **他最重要的 3～5 个任务是什么？**
>
> **最核心的一条业务任务如何从开始走到结束？**

禁止一上来直接：

> 首页 → 列表 → 详情 → 设置

而没有真实用户任务。
