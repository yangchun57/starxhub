# 1.本技能能解决什么问题

本技能 用于解决：

1. 一句模糊需求如何转成移动端产品；
2. 如何判断哪些业务适合移动端、哪些应留在 Web；
3. 如何识别现场用户、高频任务和移动使用上下文；
4. 如何把复杂业务流程压缩成短路径移动任务；
5. 如何设计首页、列表、详情、表单、审批、巡检、取证、AI识别、地图、统计看板等移动页面；
6. 如何设计底部 TabBar、返回、项目切换、FAB、底部操作栏；
7. 如何避免把 PC 表格和复杂筛选机械搬到手机；
8. 如何设计拍照、相册、视频、定位、扫码、NFC、语音等设备能力；
9. 如何设计弱网、离线、上传失败、同步冲突和断点恢复；
10. 如何设计移动端 AI 输入、识别过程、结果、依据和人工确认；
11. 如何处理键盘弹出、安全区、刘海屏、全面屏和浏览器动态视口；
12. 如何适配不同手机宽高、横竖屏和移动浏览器；
13. 如何把原型交给研发直接实现；
14. 如何形成设备级、页面级、状态级测试标准。

# 3. 第一原则：移动端不是 Web 的缩小版

任何移动端原型设计必须先回答：

> **用户为什么必须在手机上完成这件事？**

> **他最重要的 3～5 个移动任务是什么？**

> **在现场、行走、拍照、弱网、被打断等条件下，这个任务还能完成吗？**

禁止直接把 Web 的：

> 左侧菜单 + 查询区 + 表格 + Drawer

缩成手机页面。

移动端通常具有：

- 屏幕小；
- 触控；
- 输入成本高；
- 注意力碎片化；
- 易被电话、消息、锁屏中断；
- 经常在现场使用；
- 网络可能不稳定；
- 可直接调用摄像头、定位、语音等设备能力。

因此移动端页面必须重新组织任务。

# 3.1 移动端三层产品架构

本节将企业移动端统一抽象为三层。

## 3.1.1 Global Shell｜全局壳层

负责：

- 当前项目 / 组织 / 岗位上下文；
- 异常网络提示；
- Root Page Header；
- Root Navigation；
- 全局 Toast / Notice；
- 角色、权限和会话状态。

原则：

- 网络正常时不常驻“网络正常”提示；
- 弱网 / 离线时才显示异常 Banner；
- Banner 恢复后自动消失；
- 壳层不承担具体业务办理。

推荐：

```text
App Shell
├─ Exceptional Banner（异常时）
├─ Context Header
├─ Page Content
└─ Root Navigation（仅 Root Page）
```

## 3.1.2 Role Home｜岗位工作台

同一产品面向多个岗位时，首页不应只是“一套通用 Dashboard + 权限隐藏”。

应根据岗位主任务形成不同首页：

- 巡查岗位：今日任务、继续巡查、附近任务、现场取证；
- 督办岗位：待派发、整改中、逾期、待复核；
- 研判岗位：重点设施、重复异常、风险排名、治理建议。

原则：

> **岗位不同，首页主任务和 Root Navigation 可以不同；系统身份、设计语言和业务对象保持一致。**

## 3.1.3 Task Flow｜具体任务流

进入任务后，界面从“找任务”切换为“办任务”。

例如：

> 任务详情 → 到点验证 → 设施确认 → 智能取证 → AI结果 → 人工确认 → 提交。

任务层聚焦：

- 当前对象；
- 当前步骤；
- 前置条件；
- 证据；
- 主操作；
- 成功 / 失败；
- 中断恢复。

# 3.2 Root / Task / Immersive 三类页面层级

所有 P0 页面必须标记页面层级。

## Root Page

例如：

- 首页；
- 待办；
- 巡查；
- 工单；
- 风险；
- 消息；
- 我的。

默认：

- 可显示 Root Navigation；
- 无业务返回按钮；
- 主要承担入口、概览和任务发现。

## Task Page

例如：

- 任务详情；
- 工单详情；
- 整改反馈；
- 复核；
- 治理建议确认。

默认：

- 显示返回；
- 隐藏 Root Navigation；
- 可显示 Sticky Bottom Action；
- 返回关系必须明确。

## Immersive Page

例如：

- 相机取证；
- 扫码；
- 视频；
- 地图导航；
- BIM / 图纸沉浸查看。

默认：

- 隐藏普通 Header 与 Root Navigation；
- 主内容使用 Full Task Canvas；
- 仅保留必要的返回、退出、拍摄、确认控制。

口诀：

> **Root 用来找任务，Task 用来办任务，Immersive 用来完成需要最大画布的现场动作。**

# 4. 标准输入

用户不必一次提供全部信息，有什么给什么。

## 4.1 最低输入

至少需要：

1. 产品/业务是什么；
2. 主要移动用户是谁；
3. 用户为什么要在手机上操作；
4. 最重要的移动任务；
5. 使用场景：
   - 办公室；
   - 现场；
   - 户外；
   - 行走；
   - 驾驶/乘车；
   - 弱网；
   - 夜间；
6. 原型用途：
   - 项目交流；
   - 领导汇报；
   - 比赛；
   - 研发交付；
   - 正式项目；
7. 是否有 Web 端、旧 APP、H5、业务流程或现有规范。

## 4.2 增强输入

有则提供：

- 上游方案；
- Agent 设计；
- Web 端设计成果；
- PC 系统截图；
- H5/APP 截图；
- 品牌色；
- Logo；
- 设备型号；
- 目标系统：iOS / Android / 企业微信 / 微信 / 浏览器；
- API；
- 数据样例；
- 拍照要求；
- 定位要求；
- 扫码/NFC；
- 推送；
- 弱网/离线要求；
- 权限要求；
- 用户反馈。

## 4.3 不重复询问与主动推演

如果已有资料可以判断：

- 用户/岗位；
- 业务场景；
- 系统正式名称；
- 一期范围；
- 核心流程；
- 已确认业务对象与状态；
- AI/人工边界；
- 视觉基线；

则本技能必须直接继承，不重复向产品经理询问。

当信息不完整但不影响主线时，允许先做“合理假设 + 明确标记”，不得因为次要信息缺失阻塞整个产品设计。

只有当缺失信息会导致以下情况时才应提问：

- 核心业务方向可能相反；
- 权责边界不同会改变流程；
- 一期范围会发生重大变化；
- 涉及高风险合规/安全决策；
- 无法判断主任务或业务结果。

## 4.4 移动上下文卡

移动端额外识别：

| 项目 | 说明 |
|---|---|
| 使用地点 | 办公/施工现场/户外/交通场景 |
| 单次任务时长 | 30 秒 / 2 分钟 / 10 分钟以上 |
| 单手操作比例 | 高/中/低 |
| 是否需拍照 | 是/否 |
| 是否需定位 | 是/否 |
| 是否需语音 | 是/否 |
| 是否需扫码/NFC | 是/否 |
| 网络情况 | 稳定/弱网/可能离线 |
| 是否频繁中断 | 是/否 |
| 是否需要手套/强光环境 | 项目按需 |
| 是否需要大字体/高对比 | 项目按需 |

# 5. 与上游成果的衔接

## 5.1 承接上游方案

上游方案 中已确认的：

- 服务对象；
- 痛点；
- 场景；
- 闭环；
- 建设范围；
- AI 能力；
- 业务成果；

应转换为：

> **业务能力 → 移动用户任务 → 移动任务流 → 页面 → 设备能力 → 状态 → 业务结果**

## 5.2 承接 Agent 设计

如果已有 Agent：

> Agent 岗位 → Workflow → 人工卡口 → 业务结果

移动端继续转换为：

> **用户如何在现场发起 → AI 如何接收证据 → 如何看到过程 → 如何确认 → 如何进入真实业务动作**

## 5.3 与 Web 端设计成果 协同

同一产品存在 Web + 移动端时：

### Web 更适合

- 大批量管理；
- 复杂配置；
- 多列数据；
- 综合分析；
- 多对象对照；
- 长时间办公任务。

### 移动端更适合

- 待办；
- 现场采集；
- 拍照取证；
- 快速确认；
- 审批；
- 整改反馈；
- 消息触达；
- 定位；
- 扫码；
- AI现场辅助。

原则：

> **Web 与移动端共享业务对象，不机械共享页面结构。**

## 5.4 冻结原则

上游已经确认的：

- 用户；
- 核心业务闭环；
- 系统正式名称；
- 业务状态；
- AI/人工边界；
- 一期范围；

本技能 不得擅自改变。

发现移动端无法承载时，应标记：

> **MOB-DESIGN-CHANGE-XXX｜移动端设计发现的产品变更建议**

# 6. 标准流程：8 个阶段

在 8 个移动设计阶段之前，先执行“产品 Gate 0”。

## Gate 0｜产品主线成立

至少确认或合理推导：

- 为什么做；
- 谁使用；
- 最高价值场景；
- 一条完整业务闭环；
- 核心业务对象；
- 关键状态变化；
- 证据/规则/AI/人工关系；
- 一期 P0；
- 可量化业务结果。

Gate 0 不成立时，禁止直接进入视觉高保真。

进入移动端设计后执行：

1. 需求理解与移动任务定义；
2. 黄金任务流；
3. 移动上下文与设备能力矩阵；
4. 移动信息架构 IA；
5. 页面体系与页面模式；
6. 页面结构设计；
7. 交互、状态、弱网与 AI；
8. 视觉、适配与真机验收。
