# 7. 阶段 1｜《移动端原型任务理解卡》

至少包含：

- 产品一句话定位；
- 主要移动用户；
- 使用场景；
- 当前问题；
- 为什么需要移动端；
- 3～5 个核心任务；
- 单次任务期望时长；
- 核心业务结果；
- 必须调用的设备能力；
- 网络环境；
- 一期范围；
- 已知信息；
- 待确认信息。

### 需求转换公式

> **原始需求 → 用户 × 场景 × 移动任务 × 设备能力 × 网络条件 × 业务结果**

例如：

> “做设备巡检 H5”

转换为：

> 安全巡查员  
> + 施工现场  
> + 接收任务/定位/拍照/AI识别/确认隐患/提交  
> + 摄像头/定位/语音  
> + 可能弱网  
> + 形成可追溯隐患事件。

# 8. 阶段 2｜黄金任务流 Mobile Golden Flow

必须找到最能体现移动端价值的一条完整任务闭环。

例如：

> 接收巡检任务 → 到达现场 → 定位 → 拍照 → AI识别 → 人工确认 → 补充描述 → 提交 → 生成隐患工单

或者：

> 收到整改待办 → 查看隐患 → 拍整改照片 → 填反馈 → 提交 → 等待复核。

## 8.1 黄金任务流原则

1. 高频任务优先；
2. 单次路径尽量短；
3. 输入尽量少；
4. 自动带出优于手输；
5. 拍照/定位等证据一次采集、多处复用；
6. 中断后可恢复；
7. 弱网时不丢数据；
8. AI结果必须可人工修正；
9. 成功后用户知道下一步。

## 8.2 中断恢复点

黄金流必须标记：

- 哪些步骤自动保存；
- 哪些步骤可以退出后继续；
- 哪些步骤重新进入会丢失；
- 哪些操作不能重复提交。

# 9. 阶段 3｜移动设备能力矩阵

正式移动项目建议形成：

# 《设备能力与权限矩阵》

至少包含：

| 能力 | 使用场景 | 是否必须 | 权限 | 失败降级 | 数据去向 |
|---|---|---|---|---|---|
| 摄像头 | 现场取证 | 是 | Camera | 相册上传 | 事件附件 |
| 相册 | 补传照片 | 否 | Photo | 摄像头 | 事件附件 |
| GPS | 自动定位 | 按需 | Location | 手工选择 | 事件位置 |
| 麦克风 | 语音输入 | 按需 | Microphone | 键盘输入 | 文本字段 |
| QR | 识别设施 | 按需 | Camera | 手工搜索 | 设施ID |
| NFC | 设备识别 | 按需 | NFC | QR/搜索 | 设施ID |
| 推送 | 待办提醒 | 按需 | Notification | 应用内待办 | 消息 |
| 本地存储 | 弱网草稿 | 建议 | Storage | 在线表单 | 草稿 |

## 9.1 权限原则

权限申请必须：

- 在真正需要时申请；
- 说明用途；
- 拒绝后仍给下一步；
- 支持重新授权；
- 不因为非核心权限被拒就让整个产品不可用。

禁止首页一打开就一次性申请所有权限。

# 10. 阶段 4｜移动信息架构 IA

## 10.1 导航原则

- 高频任务优先；
- 层级尽量浅；
- 当前项目/组织上下文明确；
- 主导航与业务返回关系明确；
- 不把 PC 的一级菜单完整搬到手机；
- 一个页面优先一个主任务。

## 10.2 主导航 TabBar

适用于：

- 首页；
- 工作台；
- 待办；
- 巡检；
- 我的。

建议 3～5 个一级入口。

主导航页：

- 通常无返回按钮；
- 可在顶部显示项目 / 岗位上下文；
- Root Navigation 固定；
- 内容必须预留 Root Navigation + Safe Area 空间；
- **Root Navigation 仅属于 Root Page；进入详情、表单、审批、复核、取证、沉浸式地图等任务页后默认隐藏。**

## 10.3 业务页

业务页通常：

> 返回 + 页面标题 + 必要的右侧操作

禁止同时塞入过多图标。

## 10.3.1 角色化 Root Navigation

当岗位任务差异明显时，允许 Root Navigation 随岗位变化。

必须满足：

1. 角色是明确业务身份，不是随意页面模式；
2. 用户始终知道当前岗位；
3. 不同岗位可拥有不同业务入口；
4. “首页 / 消息 / 我的”等通用锚点尽量稳定；
5. 切换岗位后回到对应 Role Home；
6. 不保留与新岗位不兼容的深层任务页；
7. 路由和接口同时做权限校验，不能只靠前端隐藏按钮。

推荐路由元数据：

```text
roles
pageLevel: root | task | immersive
showHeader
showRootNavigation
```

## 10.4 项目/租户上下文

如果业务依赖项目：

> 当前项目必须明确可见。

项目切换属于上下文，不应与页面标题混淆。

# 11. 阶段 5｜移动页面体系与页面模式

本技能 不规定机械页面数量。

页面由：

> **用户任务 + 移动上下文 + 设备能力 + 业务闭环**

自然产生。

## 11.1 主导航工作台

适用：

- 我的待办；
- 今日任务；
- 快捷入口；
- 重点风险；
- 最近处理。

移动首页不要做成 PC 大屏缩小版。

## 11.1.1 岗位工作台 Role Home

岗位首页不是给所有用户展示同一组 KPI。

每个岗位优先呈现：

- 1 个主任务；
- 2～4 个状态指标；
- 1～2 个重点提醒；
- 1 组高频快捷动作；
- 少量需要立即处理的任务。

优先级：

> **“现在最该做什么” > “系统里总共有多少数据”。**

禁止：

- 一屏堆很多 KPI；
- 状态宫格、快捷入口、图表同时大量出现；
- 为了塞三列、四列而把文字压到极小。

## 11.2 卡片列表页

适用：

- 巡检任务；
- 隐患工单；
- 项目；
- 设备；
- 审批；
- 整改。

标准：

> 搜索/筛选 → Tab → 卡片列表 → 下拉刷新/上拉加载。

列表卡片优先展示：

- 标题；
- 关键状态；
- 2～4 个最重要字段；
- 时间/位置；
- 下一步入口。

不要一张卡塞 10 个字段。

## 11.3 全屏详情页

适用：

- 工单；
- 任务；
- 风险；
- 隐患；
- 审批；
- 设备。

推荐：

> Sticky Header → Tabs/分区 → 内容 → Sticky Bottom Action。

信息复杂时优先全屏页，不用小 Dialog。

## 11.4 移动表单页

适用：

- 新增；
- 编辑；
- 巡检；
- 整改；
- 审批意见。

原则：

- 纵向单列优先；
- 按业务主题分组；
- 自动带出优先；
- 选择器优先于自由输入；
- 长文本支持语音；
- 重要提交操作放底部。

## 11.5 现场取证页

适用：

- 拍照；
- 视频；
- 定位；
- 现场描述；
- 设施确认。

结构：

> 任务对象 → 位置 → 取证 → 结果 → 提交。

## 11.6 AI识别页

结构：

> 原始证据 → AI处理 → 识别结果 → 依据/建议 → 人工确认。

## 11.7 流程审批页

适用：

- 提交；
- 退回；
- 转办；
- 加签；
- 补签；
- 审核。

重点：

- 当前节点；
- 下一节点；
- 审批人；
- 意见；
- 主要操作。

## 11.8 统计看板页

移动统计页应回答：

- 当前总体怎样；
- 哪里有问题；
- 趋势怎样；
- 点哪里能钻取。

不要塞大量图表。

## 11.9 地图/GIS页

地图属于 Full Task Canvas。

建议：

- 地图尽量占主体；
- 筛选和图例轻量；
- 详情使用 Bottom Sheet；
- 定位按钮悬浮；
- 不要在地图上覆盖大面积卡片。

## 11.10 扫码/NFC页

结构：

> 扫描/感应 → 识别对象 → 确认 → 进入任务。

必须设计识别失败和手工搜索。

## 11.11 离线任务/同步中心

当业务需要弱网：

- 离线草稿；
- 待同步；
- 同步失败；
- 冲突；
- 已同步。

应有明确状态。

# 12. 阶段 6｜页面结构设计方法

每个 P0 移动页面必须定义：

1. Page ID；
2. 页面名称；
3. 使用角色；
4. 页面目标；
5. 进入条件；
6. 当前业务上下文；
7. 用户必须看到什么；
8. 用户必须做什么；
9. 主操作；
10. 页面区域；
11. 下一步；
12. 页面状态；
13. 设备能力；
14. 权限；
15. 网络策略；
16. 中断恢复策略；
17. 安全区/键盘策略；
18. 适配策略。

## 12.1 “任务—信息—动作”三层法

### 任务

用户进来要完成什么？

### 信息

完成任务必须看到什么？

### 动作

看完要点什么、拍什么、说什么、选什么？

如果一个区域不能支持其中任何一项，应审查其必要性。

---

# 12.1 上下文返回策略

移动端“返回”不等于简单调用技术路由栈。

需要定义：

- 取证页返回 → 当前任务详情；
- 事件详情返回 → 来源任务 / 工单；
- 复核返回 → 待复核列表；
- 风险建议返回 → 风险画像 / 研判首页。

原则：

> **返回到用户继续完成任务最自然的位置，而不是返回到技术 history 的上一页。**

同时兼容：

- 浏览器返回；
- Android 物理返回；
- 原生返回手势。

避免循环、跨岗位跳转和返回到失效页面。
