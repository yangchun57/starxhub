# 18. Root Navigation｜底部导航栏规范

本规范将原“TabBar”升级为 Root Navigation 规范。

它既是导航结构，也是移动产品视觉识别的重要组成部分。

## 18.1 适用范围

只用于 Root Page，例如：

- 首页；
- 巡查；
- 工单；
- 风险；
- 地图；
- 消息；
- 我的。

进入 Task Page / Immersive Page 默认隐藏。

## 18.2 数量

推荐：

> **4～5 项**

允许 3 项。

超过 5 项时优先：

- 合并低频入口；
- 将低频功能放入“我的 / 更多”；
- 重新审查 IA。

不要压缩成 6～7 个极小入口。

## 18.3 “稳定锚点 + 岗位入口”模式

这是本次从真实产品样本中沉淀的重要模式。

推荐：

```text
[稳定] 首页
[岗位] 核心入口A
[岗位] 核心入口B
[稳定] 消息
[稳定] 我的
```

不同岗位可替换中间 1～2 个入口。

例如：

```text
巡查： 首页 / 巡查 / 地图 / 消息 / 我的
督办： 首页 / 工单 / 待复核 / 消息 / 我的
研判： 首页 / 研判 / 地图 / 消息 / 我的
```

好处：

- 岗位任务突出；
- 用户仍保留稳定空间记忆；
- 不需要为三个岗位开发完全不同的 App Shell。

## 18.4 默认视觉基线

推荐基础尺寸：

| 项目 | 建议 |
|---|---|
| 基础高度 | 60～66px |
| Safe Area | 额外叠加 `env(safe-area-inset-bottom)` |
| 单项布局 | 图标上 + 文字下 |
| 图标视觉尺寸 | 20～24px |
| 文案 | 11～12px |
| 点击热区 | 每项完整单元，至少满足 44px 高度 |
| 背景 | 白色 / 高不透明白 |
| 分割 | 顶部 1px 轻边框 |
| 阴影 | 仅轻微顶部阴影，按需 |
| 当前态 | 品牌色文字 + 品牌色图标 |

## 18.5 当前态双编码

推荐当前项至少有两种视觉信号：

1. 图标 / 文字变为品牌色；
2. 增加一个轻量结构信号。

结构信号可选：

- 顶部 2px 短线；
- 极浅品牌色背景；
- 轻量圆角底；
- 图标填充态变化。

推荐默认：

> **品牌色 + 顶部短线 + 极浅背景**

但不要同时使用：

> 放大 + 强阴影 + 胶囊 + 渐变 + 发光

造成过度强调。

## 18.6 半透明 / Blur 风格的吸收原则

真实样本中的：

> 半透明白背景 + `backdrop-filter: blur(...)`

视觉较成熟，可以作为**可选高级风格**沉淀。

适用：

- 页面背景有地图、图片或层次变化；
- 设计需要轻量玻璃质感；
- 浏览器 / WebView 支持良好。

默认企业 H5：

> **高不透明白背景 + 轻边框**

即可。

Blur 不是强制规范。

## 18.7 Root Navigation 与页面内容

内容区必须预留：

```css
padding-bottom:
  calc(var(--root-nav-height) + env(safe-area-inset-bottom));
```

如果采用 Grid / Flex App Shell，也可以让导航占据独立布局行，避免内容被遮挡。

## 18.8 Root Navigation 与 FAB

当页面同时有 FAB：

FAB 的 `bottom` 必须考虑：

> Root Navigation 高度 + Safe Area + 视觉间距。

FAB 不能：

- 压住导航项；
- 遮挡最后一条数据；
- 和某个导航项视觉重叠。

## 18.9 Root Navigation 与底部业务操作

同一页面原则上不要同时出现：

> Root Navigation + 大型固定“提交 / 确认”底栏。

如果进入正式业务办理：

> 转为 Task Page → 隐藏 Root Navigation → 显示业务 Bottom Action。

## 18.10 Badge

消息 / 待办可显示 Badge。

规则：

- 仅用于真正需要用户注意的未读 / 待处理；
- 数量过大可显示 `99+`；
- 不让所有导航项都挂数字；
- Badge 不应替代页面内正式统计。

## 18.11 文字命名

导航名称必须：

- 2～4个中文字符优先；
- 任务导向；
- 不重复系统名称；
- 避免“管理中心”“功能模块”等空泛词。

## 18.12 动效

点击：

- 0.1～0.15s Active反馈；
- 当前项切换可轻微颜色过渡。

不推荐：

- 大幅弹跳；
- 图标持续动画；
- 每次切换强缩放。

## 18.13 可访问性

每项必须有：

- 图标；
- 文字；
- 当前态；
- 足够点击范围；
- `aria-label` / 语义标签（Web按需）。

不只用颜色表示当前项。

## 18.14 小屏适配

360px及以下：

- 保持4～5等分；
- 优先缩小间距，而不是把文字压到9～10px；
- 名称过长应从IA解决，不依赖两行极小字。

## 18.15 平板

平板上不机械把5个入口拉到整屏。

可根据产品：

- 保留居中有限宽度 Bottom Navigation；
- 升级为 Navigation Rail；
- 改为左侧导航。

由产品任务和屏幕形态决定。

## 18.16 Root Navigation 验收

至少检查：

- 360 / 375 / 390 / 414 / 430；
- iOS 底部安全区；
- Android 全面屏；
- 横屏按需；
- FAB共存；
- Badge共存；
- 角色切换；
- 深层任务页是否正确隐藏；
- 返回Root后当前项是否正确恢复。

# 19. 底部操作栏规范

移动端高频业务主操作优先靠近拇指区域。

## 19.1 Fixed

适合整个页面：

> 提交 / 保存 / 下一步。

必须预留内容底部空间。

## 19.2 Sticky

适合全屏详情或内部滚动容器。

原则：

> 弹窗/详情内部使用 Sticky，不要把内部按钮错误 Fixed 到整个视口。

## 19.3 安全区

推荐：

```css
padding-bottom: calc(12px + env(safe-area-inset-bottom));
```

## 19.4 操作数量

底部同时出现按钮原则上不宜过多。

推荐：

- 1个主操作；
- 1个次操作；
- 危险操作可放更多菜单或单独区域。

# 20. FAB 悬浮操作按钮规范

## 20.1 适用

- 新增任务；
- 新建记录；
- 快速拍照；
- 高频单一创建动作。

## 20.2 默认尺寸

参考基线：

> **56 × 56px**

## 20.3 位置

- 右侧约 16px；
- 底部需考虑 TabBar、安全区；
- 列表需预留空间，不能遮挡最后一条。

## 20.4 禁止

- 一个页面多个 FAB；
- FAB 和底部主按钮抢主操作；
- 不知道“+”代表什么却只用图标。

必要时使用“图标 + 文案”的扩展 FAB。

# 21. 搜索、筛选与 Tab

## 21.1 搜索

移动搜索优先：

- 一个关键词；
- 最近搜索；
- 扫码/语音按需。

## 21.2 筛选

常用筛选直接显示。

复杂条件：

> “更多筛选” → Bottom Sheet / 全屏筛选。

不在首屏堆6～10个筛选框。

## 21.3 筛选数量

首屏通常只保留最关键的 1～3 个条件。

统计看板通常更少。

## 21.4 Tab

Tab用于：

- 状态；
- 类别；
- 任务阶段。

Tab多时：

- 横向滚动；
- 不挤成极小字。

---

# 22. 列表与卡片规范

## 22.1 列表加载

移动列表优先：

- 下拉刷新；
- 上拉加载；
- 分页隐藏在交互中。

## 22.2 卡片信息层级

卡片推荐：

1. 标题；
2. 风险/状态；
3. 关键字段；
4. 时间/位置；
5. 进入详情。

## 22.3 卡片密度

一张卡片只放完成“是否点进去”所需的信息。

详情字段不要全部提前展示。

## 22.4 状态标签

风险、隐患、工单状态：

- 颜色 + 文字；
- 同一状态全系统一致；
- 胶囊标签不宜过多。

## 22.5 列表空状态

明确：

- 无数据；
- 无搜索结果；
- 无权限；
- 网络失败；

不能都显示“暂无数据”。

# 23. 详情页规范

## 23.1 全屏优先

复杂详情优先全屏。

## 23.2 内容层次

建议：

> 状态摘要 → 基础信息 → 证据 → 流程/记录 → 附件。

## 23.3 多 Tab

Tab数量可控。

复杂信息不要在一个页面无限向下堆叠。

## 23.4 照片

支持：

- 宫格；
- 大图预览；
- 左右切换；
- 原图；
- AI框选定位按需。

## 23.5 底部操作

根据业务状态动态显示。

---

# 24. 移动统计看板规范

## 24.1 第一原则

图表必须回答业务问题。

## 24.2 首屏

建议：

- 2～4 个核心指标；
- 1 个核心趋势；
- 1 个异常分布或重点提醒。

避免一屏全部 KPI。

## 24.3 指标卡

移动端可使用 2列或3列。

主数字应清楚。

不要为了塞3列把标签压到 9～10px 大面积使用。

## 24.4 图表

ECharts：

- 宽度自适应；
- 横竖屏/Resize 调用 `resize()`；
- 标签过多时横向滚动、抽样或Tooltip；
- 不在手机上塞 PC 级复杂图例。

## 24.5 钻取

可点击数字/图表必须给视觉暗示。

点击后直接带筛选条件进入列表。

# 25. 视觉设计系统

默认风格：

> **企业级、专业、现代、简洁、现场可读、有适度科技感，但不花哨。**

## 25.1 主色

参考基线：

```css
--primary-color: #4b55fa;
--primary-hover: #3b45ea;
--primary-active: #2b35da;
--primary-light: rgba(75, 85, 250, 0.1);
```

## 25.2 功能色

```css
--success-color: #37b874;
--warning-color: #faad14;
--error-color: #fa4c6e;
--info-color: #1890ff;
```

## 25.3 背景

```css
--bg-page: #f1f4fd;
--bg-white: #ffffff;
--border-color: #e4eafd;
```

## 25.4 间距

优先使用：

> 4 / 8 / 12 / 16 / 20 / 24 / 32px。

## 25.5 圆角

> 4 / 8 / 12px。

移动卡片默认 8～12px。

## 25.6 阴影

轻阴影即可。

不要每张卡都做强阴影。

# 26. 字体与移动视觉比例

本技能 对原 H5 规范进行产品级可读性增强。

## 26.1 推荐字体层级

| 层级 | 建议字号 |
|---|---:|
| 顶部页面标题 | 17～18px |
| Section标题 | 16px |
| 卡片标题 | 15～16px |
| 正文/表单 | 14px |
| 按钮 | 14～16px |
| 辅助信息 | 12～13px |
| 标签/徽标 | 11～12px |
| KPI数字 | 24～30px |
| 图表轴/极次要信息 | 10～11px，少量使用 |

### 26.1.1 小字号取舍

真实移动样本中，11px 常用于：

- eyebrow；
- 元数据；
- 状态补充；
- 导航文字；
- 次级标签。

本技能 允许**少量**11px，但必须满足：

- 非核心正文；
- 高对比度；
- 不承担关键操作理解；
- 不在强光现场承担主要阅读。

关键正文仍以 14px 左右为基线。

## 26.2 字号底线

禁止：

- 大面积 10～11px 正文；
- 为了三列布局无限缩小字；
- 长时间操作页面全部小字。

## 26.3 现场可读性

如果用户在：

- 户外；
- 强光；
- 走动；
- 戴手套；

应适当：

- 增大字号；
- 提高对比度；
- 放大操作区；
- 降低信息密度。

---

# 27. 触控尺寸与单手操作

## 27.1 点击热区

普通重要交互建议至少：

> **44 × 44px**

Android类项目可按 48px 级别设计。

如果视觉图标仅 20～24px，必须通过透明 Padding / 父容器把实际触控热区扩大到标准尺寸。

样本中类似 34×34px 的独立图标按钮可作为视觉尺寸参考，但不应直接作为通用点击热区标准。

## 27.2 主操作

主操作优先在：

> 下半屏 / 底部拇指区。

## 27.3 图标

视觉图标可以小于44px，但可点击热区不能太小。

## 27.4 危险操作

删除、撤销：

- 不紧贴主按钮；
- 二次确认；
- 避免误触。

## 27.5 不依赖 Hover

移动交互没有 Hover。

重要信息不能藏在 Hover。

# 28. 内容感知式移动布局

继承桌面端设计经验，但按移动任务重新定义。

移动页面不追求“填满屏幕”。

根据内容选择四种策略。

## 28.1 Auto Content

适用：

- KPI；
- 简短卡片；
- 提醒；
- 摘要。

> 内容决定高度。

## 28.2 Scroll Feed

适用：

- 列表；
- 工单；
- 任务；
- 时间线。

> 内容自然向下滚动。

## 28.3 Full Task Canvas

适用：

- 地图；
- 相机；
- AI取证；
- 视频；
- 扫码；
- 沉浸式审批/对照。

> 主任务使用剩余视口。

## 28.4 Bottom Sheet Task

适用：

- 选择器；
- 快速详情；
- 筛选；
- 地图对象信息；
- 短操作。

> 底部弹出，不打断当前上下文。

## 28.5 容器空置率

如果容器超过约一半面积长期没有：

- 信息；
- 操作；
- Empty说明；
- 视觉任务；

应重新审查其高度策略。

# 29. 安全区、动态视口与键盘

这是移动端必须专项设计的部分。

## 29.1 Safe Area

底部固定操作、TabBar、FAB 必须考虑：

```css
env(safe-area-inset-bottom)
```

顶部按运行环境考虑：

```css
env(safe-area-inset-top)
```

## 29.2 100vh 问题

移动浏览器地址栏会变化。

推荐实现时评估：

- `100dvh`；
- `100svh`；
- `100vh` fallback。

不要只依赖固定 `100vh`。

## 29.3 键盘

键盘弹出后必须检查：

- 当前输入字段是否可见；
- 底部操作是否被挡；
- 页面是否异常跳动；
- Picker 与键盘是否冲突。

## 29.4 长文本

输入时：

- textarea 自动扩展或内部滚动；
- 不让键盘遮住正在输入的位置。

# 30. 弱网、离线与同步

移动端正式项目必须主动评估，而不是等研发阶段再处理。

## 30.1 网络分级

- Online；
- Slow；
- Offline。

## 30.2 本地草稿

长任务建议：

- 自动保存；
- 显示“已保存本地”；
- 恢复进入。

## 30.3 提交防重

主提交按钮：

- Loading；
- 禁止重复点击；
- 使用幂等策略由研发配合。

## 30.4 图片上传

支持：

- 单张进度；
- 部分成功；
- 失败重试；
- 已成功不重复上传。

## 30.5 断点续传

大视频/大文件项目按需设计。

## 30.6 离线任务

允许离线时必须明确：

- 哪些字段可填；
- 哪些AI不可用；
- 是否可拍照；
- 是否可定位；
- 何时同步。

## 30.7 冲突

同一任务被多人修改时：

- 明确冲突策略；
- 不静默覆盖。

# 31. 响应式与多设备适配

本技能 默认以竖屏手机为第一目标。

## 31.1 必测手机宽度

建议至少：

- 360px；
- 375px；
- 390px；
- 414px；
- 430px。

## 31.2 建议整机验收尺寸

- 360×800；
- 375×812；
- 390×844；
- 414×896；
- 430×932。

## 31.3 平板

如项目需要：

- 768×1024；
- 820×1180；

应单独设计布局增强，不把手机布局无限拉宽。

## 31.4 小屏

≤360px：

- 减少并排；
- Tab支持横滑；
- 不通过大规模缩字体解决。

## 31.5 横屏

默认不要求全部页面横屏。

以下场景可重点支持：

- 地图；
- 视频；
- 图表；
- BIM/图纸；
- 大图查看。

## 31.6 图表

屏幕方向变化后必须 Resize。

# 32. 动效与反馈

移动端主要依靠：

- Active；
- Press；
- Loading；
- Toast；
- Skeleton；
- Progress；
- Haptic（原生APP按需）。

建议：

- 点击反馈约0.1～0.2s；
- 页面/Sheet约0.2～0.3s；
- 不做无业务意义复杂动画。

重要操作：

> 点击后必须立即有反馈。

# 33. 可用性与可访问性

## 33.1 颜色不是唯一信息

状态同时有：

- 颜色；
- 文本；
- 图标按需。

## 33.2 对比度

现场使用尤其保证对比度。

## 33.3 文本放大

重要项目应检查系统字体放大后：

- 不截断主操作；
- 不重叠；
- 关键内容可读。

## 33.4 读屏

正式公共服务/政务类项目按需支持语义标签。

## 33.5 错误提示

不要只说“失败”。

应说：

> 上传失败，请检查网络后重试。
